# コミットと PR の書き方

既定のままだと `feat:` を付けた英語の一行になる。この書き方に合わせる。

## 一行目

- **日本語。接頭辞を付けない。** `feat:` `fix:` `chore:` は使わない。
- **実装の手段ではなく、使う人から見た変化を書く。** 差分を読めば分かることは書かない。
- **動きのあるコミットは言い切る。** `〜する` か `〜した`。
  骨格を置く最初の1本、`PR N:` の題、記録だけのコミットは名詞で終わってよい
  （`HTTP を連打して捌ける量と遅延を測る負荷試験ツール` / `PR 1: リポジトリの骨格` / `2026-09-08 の日次点検ログ`）。
- `(#12)` は squash merge が自動で付ける。**自分で書かない。**
- **npm に出すパッケージ**で版を上げるときだけ、末尾に全角括弧で `（v0.3.0）` を足す。
  アプリの版は別の書き方をしている（lr: `0.3.0 — 再ビルドしても許可が残ることを確認した`）。

実際に使った一行:

```
ノッチのクリックでカメラの鏡を出す
別の端末にクローンしただけでビルドが通るようにする
HTTP API をやめて CLI にする
記録をアイコンの色のタイルにして、レイアウトを直す
四分割で一様なマスを単色にし、抽出色の重複を除く（v0.2.1）
使っていない API を消し、隠れていた名前と条件を直す
```

## カタカナ語を素の日本語にする

意味が通るなら置き換える。通らないなら無理に訳さない（`API` `Cookie` `cron` はそのまま）。

| 使わない | 使う |
|---|---|
| エクスポート / インポート | 控えの書き出し / 取り込み |
| ソート | 並べ替え |
| ラベル / バッジ | 札 |
| デバイス | 端末 |
| バックグラウンド色 | 地の色 |
| クラッシュする | 落ちる |
| リファクタする | 直す |

## 本文

一行で足りるなら本文は書かない。**足すのは、あとで自分が「なぜこうした」を忘れる時だけ。**
書くなら次の3つで、どれも一段落。

1. **何が困っていたか**（直した状態ではなく、壊れていた状態を書く）
2. **選んだ理由**。特に、試して捨てた案があれば数字ごと残す
3. 名前を変えた・置き場所を変えたなら、その対応

実例:

```
OGP 画像とメタデータを追加する

URL を配るのがこのツールの全部なのに、og:image どころか og:title も無く、
LINE や Slack に貼ってもプレビューが出ない状態だった。

図柄は実物のスクリーンショットではなく、専用の構図にした。
白地に細い記号のスクリーンショットは、縮小にもマス目への変換にも耐えない
（portfolio のサムネイル用に3通り試して実測した）。

generate-icons.mjs は OGP も作るようになったので generate-images.mjs に改名し、
script も images にした（shogo-site と同じ名前）。
```

## PR

- タイトルはコミットの一行目と同じ規則。`(#N)` は書かない。
- 本文は上の3点。レビュアーは自分ひとりなので、要約より**判断の根拠**を残す。
- 骨格から順に積む段階的なリポジトリでは `PR 1: リポジトリの骨格` のように番号を振ることがある（ghoi）。
  途中から始めない。既にその形式なら踏襲する。
