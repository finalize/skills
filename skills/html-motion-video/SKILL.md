# HTML で組んだ動きを動画にする

After Effects も Blender も使わず、ブラウザで描いた絵を 1 コマずつ撮って MP4 にする。
日本語の太字・縁取り・吹き出しがきれいに出て、文字を差し替えた作り直しが数分で済む。
YouTube の 10 秒のオープニングと、終了画面つきの 20 秒のエンディングをこの形で作った。

## 形

`scripts/` を作品のフォルダに写して使う（作品ごとに手を入れるので、共有の置き場から直接は読まない）。

| ファイル | 役目 |
|---|---|
| `motion_lib.js` | 道具。要素を作る・イージング・叩きつけ（`slam`）・ぽんと出る（`pop`）・吹き出しの形・縁取り文字・札・集中線・網点・揺れ・粒 |
| `<作品>.js` | 場面。`scenes.push({ g, t0, t1, update(t) })` を並べ、`init()` と `render(t)` を書く |
| `<作品>.py` | 設定（コマ数・速い区間・文字）を書いて `motion_page.run()` を呼ぶ |
| `motion_page.py` | フォントと設定を 1 枚の HTML に埋め込む → 撮る → コマごとに重ねる → 音 → 動画 |
| `capture.mjs` | Playwright で入っている Chrome を 8 個起動し、手分けして PNG にする |
| `synth.py` / `<作品>_audio.py` | 楽器と効果音の部品 / その作品の音の並べ方。最後は `master()` |
| `encode.sh` | PNG の連番と WAV を H.264 + AAC に。色の印を BT.709 に付け直す |
| `example*` | 3 秒の見本。写したら最初にこれを通す |

```sh
npm install                              # playwright-core。ブラウザは落とさず、入っている Chrome を使う
sh fetch_fonts.sh                        # Dela Gothic One / Yusei Magic（OFL）
python3 example.py --frames 1,25,40,70   # numpy の入った Python で。要所だけ描く（数秒）
python3 example.py                       # 全部 → example.mp4（M4 Max で 50 秒）
```

## 手順

1. **絵コンテを時刻で書く。** 曲の拍に合わせる。150 BPM なら 1 拍 0.4 秒 = 12 コマ。
   叩きつける瞬間を強拍に置くと、音と絵が勝手にそろう。
2. 場面を書き、`--frames` で要所だけ描く。`tile=3x4` で 1 枚に並べて見て、要所は原寸でも見る。
3. 音を書く。**耳で確かめられないので数字で見る。** 帯域ごとの量、0.5 秒ごとの RMS、
   スペクトログラム（`showspectrumpic`）で鳴る時刻を、絵の時刻と照らす。
4. 全部を書き出し、できた MP4 を 1 秒おきに並べて見る。
5. 渡す先に大きさの上限があれば、別に軽い版を作る（CRF 16 → 20 で約 1/3、PSNR 46 dB）。元は残す。

## 決まり

- **見た目は時刻 t だけで決める。** 前のコマの状態を使わない。乱数は種を決めた `rng(seed)`、揺れも t の連続した関数（`shakeAt`）。
  これで何個並べて撮っても、撮り直しても同じ絵になる（8 並列と 1 個で、バイト単位で一致した）。
- **動きのぼかしは 1 コマを分けて撮って平均する**（シャッター 0.5 コマ）。止まっているところ 3 枚、ふつう 6 枚、
  叩きつけ・画面を振る・ズームは 24 枚。区間は `windows=[(t0, t1, 24), ...]` に時刻で書く。6 枚一律だと速い所が残像の段になった。
- **画面を横（縦）に振るところは、24 枚でも残像が段になる。** 速さに比例した片方向の `feGaussianBlur`（`stdDeviation="sd 0"`）を足す。
- **フォントは base64 で HTML に埋め込む。** file:// のページから別ファイルのフォントを読ませると Chrome がはじくことがある。
  文字の幅（札の幅など）は `setupStage()` がフォントを読み終えてから測る。
- 縁取りは SVG の `paint-order: stroke`（外に太る）。`-webkit-text-stroke` は字に食い込む。二重の縁は同じ text を 2 枚重ねる。
- **YouTube の終了画面の区間は、要素が出そろったら画面を一切動かさない**（揺れもズームも）。YouTube 側の枠は動かないので、ずれて見える。
- 音は平均 −15〜−16 dBFS、ピーク −1 dBFS。声を乗せる区間は曲を 4〜5 dB 下げる。
- 分けて撮った画像は 1 枚 2.5 MB、20 秒で約 10 GB になる。`run()` は重ね終えたら消す（残すなら `--keep`）。

## 踏んだ罠

- **長く撮ると Chrome が落ちる**（3,942 枚の 1,255 枚目で止まった）。`capture.mjs` は落ちたら起動し直して続きから撮り、
  800 枚ごとにも起動し直す。Node が終了コード 13 で止まったら、待っていた応答が来ないまま終わった＝Chrome が落ちて接続が切れた。
- **Chrome はタブでなく別々に起動する。** 画面の合成と PNG 化は Chrome 本体のプロセスがほぼ 1 コアで受け持つので、
  タブを増やしても本体で詰まる。M4 Max で 1 個 0.26 秒/枚 → 4 個 0.078 → 8 個 0.047 → 12 個 0.043。8 個を既定にした。
- 起動直後の 1 枚だけ、数画素が 1 階調ずれることがある（PSNR 107 dB）。見て分かる差ではない。
- `drop-shadow` を拡大縮小する `<g>` に付けると、影のずれも一緒に拡大される。変形していない親に付ける。
- `clipPath` の座標は、それを使う要素の座標系。変形した `<g>` の中で使うなら、その中心からの座標で書く
  （文字の上を光が走る切り抜きが、吹き出しの外にずれた）。
- 動く文字と重なる札・ラベルは、コマごとに重なりを調べて薄く消す。一瞬くぐるだけ（12 コマ未満）なら消さない。消すと点滅に見える。
- PNG の sRGB の印が MP4 に引き継がれて `iec61966-2-1` になる。`encode.sh` の `setparams` で BT.709 に付け直す。
- 60 Hz 以下の重低音は小さなスピーカーでは聞こえないのに、音量の上限を食う。全体の −7 dB あったのを −11 dB まで削った（`tone_shape`）。
- 曲をテープのように止める演出では、残したくない効果音の余韻も曲の側に置く。別にしておくと「…」の間にも鳴り続けた。
