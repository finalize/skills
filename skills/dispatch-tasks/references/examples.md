# 実例

割り振りで実際に起きたこと。`SKILL.md` のどこの話かを見出しにした。

## 手順1: 同じ作業が無いかを見る

- 2026-11-20、メニューの開け閉めのチケットの前に、同じ日の別の PR がメニューを組み替えていた。

## 手順2: 同じファイルを触るものは1つの子に束ねる

- ボタンの位置を直すチケットと、文言を置き換えるチケットは、どちらも同じ画面のファイルを書き換えるので1つにした。

## 手順4: 番号の予約は目安

- あるチケットに予約した spec の番号を、司令塔の外の作業が先に使った。

## 手順4: 皆が触るファイル

- 索引の README で、2つの PR が衝突した。

## 地雷: 子が多いと、全体の検査が重なって時間切れが出る

- load 75 で E2E が1件落ちた（単独なら通る）。
- 2026-11-21 は4人が同時にコミットの検査とシードを回し、10コアで load が 190 を超えて、触っていないテストが5〜6件ずつ時間切れになった。
