# fix-with-evidence の出どころと、測った記録

`SKILL.md` を使うときに読む必要はない。直すときと、効き目を疑うときに読む。

2026-11-21 に、この記録を `SKILL.md` から移した。手順と実例は変えていない。
同じ日に、実例も `SKILL.md` から `references/examples.md` に移した（スキルを特定のリポジトリの話に寄せないため）。中身は変えていない。
下の「確かめたこと（2026-10-23）」は、実例が本文にあった形でのもの。移した後の形は、2026-11-22 に測り直した（いちばん下）。

## 出どころ

手順は pstack（Lauren Tan、MIT）の bug-fix と perf-issue の playbook、principle の fix-root-causes・attack-the-premise・
prove-it-works・explain-the-number から、既定の振る舞いを変える部分だけを取った。https://github.com/cursor/plugins/tree/main/pstack
実例は、自分の Claude Code の会話履歴（2026-07〜10）から拾った。

## 確かめたこと（2026-10-23）

Opus 5.5（xhigh）に `claude -p` で同じ依頼を流し、スキルあり・なしで比べた（各1本、MCP なし、自動モード）。
題材は koimoyou の複製。見出しを 64px に固定したコミットの上に、無関係なコミットを1つ積み、見当の外れた報告をした。
「320 幅のスマホで見ると、最初の画面の見出しが左右の端までくっついて、文字が切れてる。.hero の overflow: hidden が怪しい気がする。直して」。
`overflow: hidden` を外すと、菱形の飾りでページが横に広がり、かえって悪くなる。

採点は外から、直した後の状態をビルドして、ヘッドレスの Chrome で 320・390・1280 幅の見出しの左右の端を測った。

| | 時間 | 費用 | 見当（`overflow: hidden`）の扱い | 直し方 | 採点 |
|---|---|---|---|---|---|
| なし | 2分7秒 | $0.61 | 菱形の飾りを切るのに要る、と読んで残した | `min(64px, calc((100vw - 40px) / 5.2))` | 320 幅で 23〜297 に収まる。390 幅以上は 64px のまま |
| あり | 2分56秒 | $0.82 | 実際に外し、ページが 434px に広がるのを見てから残した | `clamp(36px, 17vw, 64px)` | 320 幅で 21〜299 に収まる。390 幅以上は 64px のまま |

- どちらも、直す前に 320 幅で測って再現し（-3.2〜323.2）、原因のコミットを特定し、見当を退け、大きくした意図を残して直し、
  直した後に幅を変えて測った。手順の大部分は、Opus 5.5 には当たり前だった
- スキルで変わったのは確かめ方。見当を推論でなく実験で退け、本番と同じ配信（`cf-wrangler dev`）で測り、3ページを8つの幅で調べた
- 時間と費用は1.3〜1.4倍。本数が少なく題材も1つなので、傾向どまり

## 実例を移した後の測り直し（2026-11-22）

実例を本文から `references/examples.md` に移して、振る舞いが変わっていないかを見た。上と同じ題材（複製を作り直した）と同じ依頼で、
移す前の形（本文135行）と移した後の形（本文86行と `references/examples.md`）を、同じ日に1本ずつ流した。
Opus 5.5（xhigh）、`claude -p`、MCP なし、自動モード、Claude Code 2.1.330。採点も上と同じ。

上と変えたところ:

- `--setting-sources project` を付け、スキルは題材の `.claude/skills` に置いた。個人のスキルと個人の `CLAUDE.md` を読ませないため
  （いまは、このスキル自体が個人のスキルとして入っている）。`/context` で、見えるスキルがこの1つだけなのを見てから流した
- スキルの `references/measured.md` は、どちらの形からも外した。この題材の答え（原因と直し方）が書いてある
- スキル無しは流していない。比べたのは、移す前と後

| | 時間 | 費用 | 見当（`overflow: hidden`）の扱い | 測った配信 | 調べた範囲 | 直し方 | 採点 |
|---|---|---|---|---|---|---|---|
| 移す前 | 2分50秒 | $0.84 | 外して測り、文字の位置は変わらずページが 434px に広がるのを見て残した | `vp preview` | 3ページを8つの幅 | `min(64px, calc((100vw - 40px) / 5.1))` | 320 幅で 20〜300 に収まる。390 幅以上は 64px のまま |
| 移した後 | 3分4秒 | $0.92 | 同じ | ビルドして `wrangler dev`（本番と同じ形） | 見出しは9つの幅、同じ型の誤りは3ページを2つの幅 | `clamp(36px, 16vw, 64px)` | 320 幅で 29〜291 に収まる。390 幅は 62.4px で、64px になるのは 400 幅から |

- どちらもスキルを呼び、直す前に 320 幅で測って再現し、原因のコミットを特定し、見当を実験で退け、大きくした意図を残して直し、
  直した後に幅を変えて測り、起こしたサーバーを止めて終えた。上で「スキルで変わった」と書いた確かめ方は、移した後の形にも残っている
- 移した後の形は、`references/examples.md` を開かなかった（Read の記録に無い）。開かなくても、上の振る舞いは出た
- 違いは、測った配信、調べた幅の数、390 幅での大きさ。各1本なので、形の違いによるものか、1本ごとの揺れかは分からない
- デプロイと push に当たるコマンドは、どちらも流していない（記録を数えて0）
