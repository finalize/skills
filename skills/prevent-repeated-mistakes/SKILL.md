# 同じ指摘を二度させない

既定のままだと、指摘された AI は謝って、CLAUDE.md かメモに一行足す。読まれなければ何も止めない。
次の会話のエージェントは、開いたファイルしか見ず、近くの例を写し、通る中でいちばん短い道を取る。
このスキルは、指摘を「書いておく」から「起きなくする」に変える。

## 向くとき・向かないとき

- 向く: 「また」「前にも言った」「何度目」と言われたとき。同じ型の直しのコミットが2つ以上あるとき。
- 向かない: 1回きりの誤り（まず直すだけ）。
- かかるもの: 測った1件では、時間も費用も1.3倍（下の「確かめたこと」）。

## 手順

### 1. 誤りの型を集める

- いまの指摘に加えて、同じ型が前にもあったかを探す。git log（revert、「直す」「戻す」のコミット）、PR のレビュー、
  CLAUDE.md とメモ、会話履歴
- 2回起きたら型として扱う
- 会話履歴をまとめて抜き出すと、自動モードの分類器が個人情報の扱いとして止めることがある（2026-10-23）。
  回り込まず、本人に読んでよい範囲を聞く。許可をもらってから流し直すと通った

### 2. 上の段から順に、起きなくする

1. **構造でなくす。** 状態の持ち主を1つに、やり方を1つにする。古いやり方と、写されそうな死んだコードを消す。
   手で揃えている一覧は、1つの源から作る。道具の設定で誤りの出どころを消せるなら、それもこの段。
   Claude Code なら、コミットの共同編集者の行は settings の `attribution`、応答の言語は `language`、
   Bash ツールのシェルは環境変数 `CLAUDE_CODE_SHELL`（文書にある手段。2026-10 時点）
2. **型で書けなくする。**
3. **lint・CI・フックで止める。** エラーの文面で、代わりに使うファイル・型・関数・コマンドを名指しする。
   すでに多い型なら、増えたときだけ落とす。git のフック（コミット前、コミットメッセージ）と、
   エージェントのフック（Claude Code なら PreToolUse で、道具の呼び出しを止める）もこの段。
   PreToolUse のフックは exit 2 で止め、stderr に代わりのコマンドを書くと、それがエージェントに届く
4. **テストで振る舞いを固定する。** 書き方は effective-tests
5. **文書は最後。** 判断が要るものだけ。書いても、飛ばされたときに何も落ちない。
   書くなら、その誤りが起きる会話で必ず読まれる場所に書く。Claude Code のメモ（auto memory）は git のリポジトリごと
   （git の外ではそのディレクトリごと）で、ほかのリポジトリの会話には読まれない。全部の会話に効かせるなら
   `~/.claude/CLAUDE.md` か `~/.claude/rules/`

上の段で止められるなら、下の段で済ませない。下の段にしたなら、上の段で止められない理由を書く。

### 3. 過去の実際の誤りで止まるのを見る

- 足した仕組みに、過去の誤り（実際のコミット、差分、コマンド）を流して、落ちるのを見る。落ちない仕組みは守っていない
- 正しいものは通ることも見る。止めすぎる仕組みは、外されて終わる
- 手元と CI で同じコマンドにする
- 例外は、その行に理由と期限を書く

### 4. 決まりの表を持つ

エージェント向けの文書（CLAUDE.md）に、決まりと、それを止めている仕組みを並べた表を置く。

| 決まり | 止めるもの | 起きたこと |
|---|---|---|

指摘されたら、直して表に足す。表にあったのに止まっていなかったら、それは繰り返しなので、同じ変更で上の段に上げる。
起きようがなくなった決まりは消す。

## 実例

自分の会話履歴（2026-07〜10）で、実際に起きたこと。

### 上の段で止めたら、止まった

- **設定で止めたら、160回で0件になった**（2026-10、仕事のリポジトリ）。「コミットメッセージに共同編集者=claude みたいな文言は不要」と言われ、
  settings の `attribution` で止めた。以後のコミットと PR の操作160回で0件だった
- **言語を設定に上げた**（2026-10-23）。下の「メモはプロジェクトの外に届かない」を受けて、`~/.claude/settings.json` に
  `"language": "japanese"` を足した。足した直後から、会話の指示に「Always respond in japanese」が入った（効いたかは、まだ数えていない）

### 文書の段では、止まらなかった

- **メモはプロジェクトの外に届かない**（2026-09〜10）。9/27 に Sagashi で「日本語で頼む」と言われ、メモに残した。
  メモは `~/github.com/finalize` で始めた会話にしか読み込まれず、約22時間後の `~/workspace` の会話では、途中経過の61行中48行が英語だった。
  メモが読み込まれていた会話でも、翌日には AI の発言の87中45が英語に戻った。
  上の段の手は、`~/.claude/settings.json` の `"language": "japanese"`（全プロジェクトに効く、文書にある設定）
- **報告しただけでは止まらない**（2026-10）。10/12 に hidori の og:image が `*.shgysd.workers.dev` で引けないと見つけたが、報告で終えた。
  4日後の koimoyou で、同じ見込み違いのまま SITE_URL を書いた
- **同じ地雷を、会話をまたいで何度も踏んだ**（2026-09〜10）。zsh の一致しないグロブで止まったのが5つの会話で10回
  （`--include=*.swift` など。メモにあったのは `rm` の例だけ）。macOS に `timeout` が無く exit 127 になったのが4つの会話。
  `grep` の正体が ugrep で、日本語と `.{0,300}` で complexity limits に当たったのが4回。zsh の組み込み `log` とぶつかったのが3回
- **書いた本人が、30分後に踏んだ**（2026-10-23、このスキルを作ったとき）。make-verify-skill の罠に「zsh では変数が空白で分かれない」と
  書いたあと、測定の準備で `GIT="git -c user.name=…"; $GIT add -A` と書き、コマンドが見つからずにコミットが1つも作られなかった。
  文書は、書いた本人の手も止めない
- **確かめずに言い切った**（2026-10、仕事のリポジトリで約9回。本人が見つけたのは4回）。「Claude Code は AGENTS.md を読まない」
  「gh では動画を添付できない」のように、古い知識で「できない」と言い切った。判断の問題なので文書の段に置くしかないが、
  置くなら全部の会話で読まれる場所にする
- **効き目を測っていないスキルは消した**（2026-10-17）。shogo-commit-style など5本は呼ばれてはいたが、効いたかは測っていなかった。
  スキルも文書の段に入る

## 出力

1. 誤りの型ごとに: 証拠（いつ・どこで）、選んだ段、上の段にしなかった理由
2. 過去の誤りで落ちるのを見た記録と、正しいものが通るのを見た記録
3. 決まりの表の差分

## 出どころ

pstack（Lauren Tan、MIT）の correct から、既定の振る舞いを変える部分だけを取った。https://github.com/cursor/plugins/tree/main/pstack

## 確かめたこと（2026-10-23）

Opus 5.5（xhigh）に `claude -p` で同じ依頼を流し、スキルあり・なしで比べた（各1本、MCP なし、自動モード）。
題材は koimoyou の複製で、実際に 2026-10-16 に起きた件をそのまま頼んだ。「手元で `pnpm run ship` したら、CI でしか走らない門番のテストを
素通りして公開された。前にもあった。もう起きないようにして」。

採点は外から、直した後の状態で `ship` を2回流して見た。門番が落ちる状態でデプロイの段に進まないか、門番を満たすと進むか。
本物には上げないよう、`cf` は無効なトークンで認証に落としてある。

| | 時間 | 費用 | 直した段 | 過去の誤りを流して確かめたか | 採点 |
|---|---|---|---|---|---|
| なし | 257秒 | $1.20 | 構造（`ship` が先に `ready`）＋ `ship` の形を固定するテスト | 流さず、`ready` の終了コードから推論 | 両方合格 |
| あり | 339秒 | $1.52 | 構造（同じ）＋ CI の検査も `ready` の1か所に＋決まりの表 | 流した。直す前は進み、直した後は止まり、正しい値なら進む | 両方合格 |

- この件は、スキル無しでも構造の段で直した。スキルで変わったのは確かめ方で、過去の誤りを実際に流し、止めすぎないかも見た。
  ほかに、検査の源を1つにしたこと、決まりの表、残った抜け道（`cf deploy` を直接打つ）をフックで止める提案。
- スキル無しは、残った抜け道を CLAUDE.md に書くだけで終えた。
- 時間と費用は1.3倍。本数が少なく題材も1つなので、傾向どまり。
- 測った後で、手順の段1・3・5に Claude Code の設定とフックとメモの範囲の説明を、実例に2件を足した（手順の形は同じ）。
